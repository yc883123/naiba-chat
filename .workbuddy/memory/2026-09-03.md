## 提示词层级调研（只调研，未改码）

结论：会话「系统提示词」与 Agent「提示词」**不是两层，是被拼成同一段**。

- 唯一拼接点 `async_tasks.py:1020-1025`：
  `prompt = "\n\n".join([agent.system_prompt, conversation.system_prompt])`，Agent 段在前。
  - 轻量直连（`lightweight_direct`）时第一项被强制置空 → **Agent 提示词被静默丢弃**。
- 注入点 `skill_runtime.py:1367-1368`：`system += "\n\n用户配置的 Agent 指令：\n" + prompt`
  → 两段**共用同一个标题**，模型分不出来源、分不出优先级（冲突时靠位置：会话段在后隐性覆盖）。
- system 内部顺序：固定规则+工作区+工具清单+脚本优先指南 → ②「用户配置的 Agent 指令」合并块 → ③ 冻结 Skill 块。
  → 改 ② 的任一处，② 和 ③ 一起破前缀缓存；③（SKILL.md 全文）通常最占体积，代价最高。
- 第三个孤儿配置：`config.json` 顶层 `agent_system_prompt`
  - 前端 `public/` 零引用 → 无 UI 入口；主聊天链路不读。
  - 只有 `subagent.py:85-86`、`plan_runtime.py:722-723` 在「Agent 提示词为空」时兜底读。
  - `server.py:1274/1301` 仍允许通过设置 API 写入（截断 12000 字符）。
- 长度上限：Agent 提示词 12000（`server.py:1805`）；会话系统提示词 20000（`storage.py:709`）。
- 会话系统提示词是**会话内唯一可随时改且立即生效的 system 段**（snapshot 每轮现取）。

### 补充事实（会话系统提示词的传播与可见性）

- **会被子 Agent 与计划执行继承**：`subagent.py:88-89`、`plan_runtime.py:725-728` 都会把
  `conversation.system_prompt` 与 agent prompt 拼接后作为子任务的 prompt。
  → 写在对话提示词里的红线，派出去的子 Agent 也吃得到（Agent 提示词同样继承）。
- **UI 可见性极差**：`public/app.js` 中会话系统提示词只在 2754（读）/2770（写）两处，
  即对话设置弹窗内的 textarea，主界面无任何"已设置/未设置"指示。
  对比：Agent 提示词在 `app.js:3559` 会渲染到 Agent 列表卡片上，是可见的。
  → 用户反馈"对话规则没用"的根因大概率是**发现不了 + 看不见生效**，不是功能无用。
