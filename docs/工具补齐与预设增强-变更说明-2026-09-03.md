## 二、工具补齐四项（对照 CodeBuddy / Codex / DeepSeek Harness 缺口）

依据 `docs/工具补齐方案-2026-09.md` 落地实施，四项全部为**纯标准库实现**（`urllib` / `html.parser` / `difflib` / `sqlite3`），不新增第三方依赖，避免 PyInstaller 打包膨胀。

### 2.1 fetch_page —— 抓取并提炼网页正文（新增，归「网络」组）

抓取 http/https 页面，剔除导航、页脚等噪音后提炼为 Markdown 正文，返回：页面标题 / 来源 URL / 正文要点 / 页面内链接清单。

- 实现：`html.parser.HTMLParser` 子类 `_HtmlArticleExtractor`，收集 `<title>`（先于忽略检查，保证 `<head>` 内的标题不丢失），忽略 `nav` / `footer` / `head` / `script` / `style` 等噪音块，块级标签换行，链接提取为 `[文字](url)`。
- 读取上限：`min(max(max_chars * 6, 64KB), 3MB)`，防超大页面拖垮上下文。
- 非 HTML（如纯文本、图片）与需 JS 渲染的动态页分别给出降级提示。
- 默认需要权限确认（与 `web_search` 同级，属 `DANGEROUS_TOOLS`：`"fetch_page": "抓取并提炼网页正文"`）。

**为什么不用第三方解析库：** 避免 `bs4` / `readability` 进入打包产物；本次采用纯标准库方案，能力足够覆盖正文提炼场景。

### 2.2 search_files —— 正则搜索增强（扩展，仍归「文件读取/搜索」组）

在原有子串搜索基础上新增 4 个参数：

| 参数 | 说明 |
|---|---|
| `regex` | 传正则表达式时按正则匹配（不传则保持子串匹配，兼容旧调用） |
| `ignore_case` | 忽略大小写（默认 false） |
| `context_lines` | 命中行前后各取 N 行上下文，输出带行号 |
| `multiline` | 跨行正则（`.` 可匹配换行），输出匹配块的行号区间 |

实现要点：单文件走 `_search_one_file`——子串模式输出旧格式 `path:line: content`；正则模式按行匹配带上下文；多行模式用 `re.DOTALL` 全文匹配后以 `bisect` 反查命中块跨过的行区间。命中上限 100 处，防止失控。

> 兼容性：不传新参数时行为与 1.6.9 旧版完全一致（子串搜索 + `path:line:` 格式），旧会话调用不受影响。

### 2.3 recall_history —— 跨会话记忆检索（新增，归「会话与记忆」组）

在**全部历史会话**中按关键词检索消息内容，返回命中消息所属会话、角色、内容与时间，用于让 AI 回想起"之前讨论过的那件事"。

- 实现位置：`server.py` `_recall_history_handler`，走 `storage.ChatStorage`（SQLite WAL）。
- 匹配方式：`instr(lower(m.content), lower(?)) > 0`——大小写不敏感、**通配符安全**（用户输入 `%` `_` 不会触发 LIKE 语义），无需 `ESCAPE`。
- 排序：`ORDER BY m.created_at DESC`（按消息时间倒序，最新相关记忆优先），上限 400 条。
- 参数：`query`（必填）、`max_results`（可选）。

> 踩坑记录：最初版本用了 `LIKE ? ESCAPE '\'` + `ORDER BY m.msg_created`，前者在 Python 引号转义下不稳定、后者引用了不存在的列别名；均已在实现期修正为 `instr` 方案，见下方案例代码。

```python
rows = dbc.execute(
    "SELECT c.id AS cid, c.title AS title, c.updated_at AS conv_updated, "
    "m.role AS role, m.content AS content, m.created_at AS msg_created "
    "FROM messages m JOIN conversations c ON c.id = m.conversation_id "
    "WHERE instr(lower(m.content), lower(?)) > 0 "
    "ORDER BY m.created_at DESC LIMIT 400",
    (query,),
).fetchall()
```

### 4.4 ComfyUI 预设只走 HTTP、不启 MCP（本轮关键调整）

现状：连 ComfyUI 有两条通道——**HTTP 原生**（`comfyui_prepare_workflow` / `comfyui_batch`，直连本机 8188）与 **MCP**（config 中 `comfy-mcp` server 动态注册 `mcp__comfy-mcp__*`）。

为保证「ComfyUI 预设 = 纯 HTTP 通道」成为**显式保证**（而非靠分组碰巧不包含），`resolve_tool_preset` 新增 `exclude_mcp` 语义：

```python
if preset.get("exclude_mcp"):
    selected = {
        n for n in selected
        if not n.startswith("mcp__") and n not in ("register_mcp", "call_mcp")
    }
```

即：预设声明 `exclude_mcp: True` 后，无论 include 将来怎么展开、MCP 服务将来怎么增加，都会强制剔除 `mcp__*` 与 MCP 网关入口。`comfyui` 预设已声明 `"exclude_mcp": True`，描述同步注明「走 HTTP 通道直连本机 ComfyUI，不启用任何 MCP 连接」。

**验证**（模拟 `comfy-mcp` 注册 run_workflow / get_progress 两个动态工具后展开）：minimal=5、standard=11、research=14、batch=20、comfyui=**21（mcp_contained=False）**、full=35→**37（mcp_contained=True，含 2 个 mcp__ 工具）**；`mcp__` 工具组归属 = `['MCP', 'MCP']`。

## 五、Bug 修复：删除 Agent 后新建会话报「Agent 不存在」

### 现象

删除某个自定义 Agent 后，点「新建会话」——前端 `createConversation` 会沿用上一个会话记录的 `agent_id`；若该 Agent 已被删除，后端直接 400「Agent 不存在」，新建链路中断，顶栏异常不显示。

### 根因

两层缺失：后端对「传入不存在的 agent_id」一律 400 拒绝，没有兜底；前端沿用上一会话 agent_id 前未校验其有效性。

### 修复

1. **后端（`server.py` `POST /api/conversations`）**：显式传了不存在的 `agent_id` 时**静默回退默认 Agent**（`default_agent_id()` 恒返回有效 id），不再 400 拒绝——会话照常创建，顶栏不受影响。
2. **前端（`public/app.js` `createConversation`）**：发请求前以 `bootstrap.agents` 为白名单过滤上一会话 agent_id，源头就不发死 id；无上一会话时回退 `bootstrap.default_agent_id`。

同时确认：`DELETE /api/agents/<id>` 本就会重置 `default_agent_id`，且删除后前端会 `refreshAgentsFromServer()` 同步列表；用户主动在会话设置里切换 Agent 的下拉只含有效 Agent，仍保持报错合理（未改动）。

### 验证

- **API 级**（隔离实例 8878）：建临时 Agent → 用它建会话 → 删除 Agent → 沿用死 id 建会话 → **201 创建成功，agent_id 自动回退 `general`**；显式传有效 id（dsh-standard）仍正常直达；bootstrap 中临时 Agent 已不在列表。
- **CDP UI 级 8/8**：模拟当前会话指向已删 Agent → 点「新会话」→ 请求体正确回退 `general`、无报错、顶栏 Agent 下拉正常。
