## 一、项目与重构目标（必读）

- **Naiba Chat**：Windows 本机 AI 自动化工作台——本地 HTTP 服务（端口 8765）+ pywebview 桌面壳；对话、内置工具、后台 Job、Skill、MCP、视觉路由、ComfyUI、更新器、SQLite 存储都在这一个进程里。
- **重构目标**：根目录约 20 个 Python 文件（原 `server.py` 5575 行等）迁入 **`naiba/` 包**（领域分层、单向依赖、组合根唯一），`server.py` 最终退化为门面；HTTP API 与事件协议**版式不动**；前端不需要配合（插话前端控件已在 2026-09-06 一并移除）。
- **哲学四支柱（§0.6）**：① 分层单向 DAG（三类边：import / 运行期调用 / 契约；目录只是投影）；② 边显式化（延迟导入清零、注入/Protocol，禁用全局 APP 中转与字符串键）；③ 机械可验证（`tests/test_dependency_dag.py`：无环 + naiba 不 import server + core 只依赖叶子）；④ 结构≠行为（护栏测试 + 每阶段编译实测护航）。
- **阶段状态**：阶段 0（修复+护栏）✅ / 阶段 1（core 纯函数迁出）✅ / 阶段 2 ✅（run 包 session/stream/manager+chat、tools 声明+执行、skills agent/catalog/install/policy/context、storage 包、llm/vision 整模块、mcp/jobs/plans/subagent/search/capability/updater/net 归位）/**阶段 3 ✅（2026-09-06 完成）**：3.4.1 paths/config（PathContext 注入化 + ConfigStore 迁入 naiba/config.py）→ 3.4.2 app/http（NaibaChatApp → naiba/app.py；RequestHandler → naiba/http.py + AppHTTPServer 注入组装）→ 3.4.3（server.py 收口门面 + 全部内联业务下沉为 NaibaChatApp 方法，HTTP 层仅剩薄包装与传输职责）。
- **当前代码布局（阶段 3 后）**：`server.py`（136 行门面：PC/路径常量/APP 注解/naiba 侧 re-export/三个薄委托 write_status/acquire_instance_lock/main + `__main__`）；`launcher.py`（仅 AppHTTPServer 构造改为注入式，其余未动）；14 个根 shim（`from naiba.X import *`）+ `_cancel_regression.py`/`_smoke_harness.py` 手工脚本；`naiba/` 内部：`app.py`（NaibaChatApp + 全部 api_* 业务方法，`_reply` 约定返回 (payload, status)）、`http.py`（RequestHandler 薄包装 + AppHTTPServer + 服务生命周期三函数）、`config.py`、`paths.py`、`core/`、`storage/`、`run/`、`tools/`、`skills/`、`llm/`、`vision/`、根级 `net/mcp/jobs/plans/subagent/search/capability/updater`。

## 三、事故教训与搬移守则（七条，权威版见 §0.6⑤）

1. **三步验收**：① 导入系统性核对——「完整未定义名扫描」：AST 收集全部 Store 绑定（含 lambda/except-as/推导式），报任何 LOAD 无绑定者；剩余候选多为 except-as/注释误报，**人工核实**（注意：扫描器自身已知缺陷——`visit_Lambda` 未收集 vararg/kwarg，`**kw` 参数会误报，核实过后视为无问题）；② 全量 `unittest`（当前 70 个）；③ 冒烟必须 `GET /api/health` + `GET /api/bootstrap` **都 200**（bootstrap 覆盖 Skill 扫描等装配路径——只验 health 曾漏掉 Skill 路径 500）。
2. **顶层定义集 diff**：搬出文件定义集 == 目标文件定义集 ∪ 剩余文件定义集（防误搬/漏搬：SkillCatalog 裹挟、`_frontmatter_value` 误删、常量误卷三次教训）。
3. **禁用「凭印象拼导入清单」**：优先**原样复制源文件头部导入块**；新增依赖由「未定义名扫描」兜底——必须覆盖**混合大小写**（`normalize_skill_policy` 曾被"大写常量扫描"漏掉）。
4. **改写型手术风险远高于整体搬移**：能整类/整模块搬就整搬（已成功案例：SkillAgent 整类、ToolExecutor 整类、ChatStorage 整模块、model/vision_runtime 整模块）；必须改写时先做原文本引用/行为等价核对。三次连环事故全部源于"方法→函数"改写——**已回退，现阶段一律不做方法改写**（protocol/context 纯函数化属暂缓项）。
5. 每逻辑单元独立提交；每阶段后 PyInstaller 编译一次并交用户实测；编译因 naiba-chat 进程占用失败时，**允许直接 `Stop-Process -Name naiba-chat -Force`**（已实际操作过）。
6. **提交卫生**：显式 `git add <文件清单>`（**勿用 `-A`**——`build_info.json` 每次编译滚动、`.tmptest/` 为沙箱本地产物，均已排除；`.tmptest/` 已在 .gitignore）。
7. **环境纪律**：PowerShell 内联 `python -c "…"` 会破坏转义（多次假警报根源）——验证脚本一律写到 `.tmptest/*.py` 再执行，并设 `PYTHONPATH=D:\naiba-chat`；输出中文乱码是控制台 GBK 显示问题，不影响内容。

## 八、技术雷区速查

- `server.py` 的 `APP` 全局不可在运行时模块中继续隐式共享（哲学②）——阶段 3 机械替换为注入；`APP` 引用约 199 处。
- `DATA_DIR` 在 `NaibaChatApp.__init__` 曾有二次重绑定语义（路径注入化时保留此语义，勿让 import 顺序改变取值）。
- `STATIC_ASSET_VERSION` 现为 import 时磁盘 I/O——lazy-once 缓存，禁止每请求重算。
- comfy-mcp 本机连接：health/bootstrap 返回其工具清单，属正常；杀进程时一并注意。
- `launcher.py` 顶层 `import server as srv`——门面收口后必须保持 `srv.RequestHandler/APP/STATUS_PATH/RESOURCE_DIR/write_status/acquire_instance_lock/NaibaChatApp/main` 可达。
- 冻结版/源码双路径（`sys.frozen`/`_MEIPASS`/`%LOCALAPPDATA%\NaibaChat`）是 3.4.1 最大变数：改后**必须**出一次冻结版实测（正是 §0.6④ 要求的流程）。
