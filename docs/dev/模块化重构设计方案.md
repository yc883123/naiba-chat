# Naiba Chat 模块化重构设计方案

> v0.1 草案（待评审）。范围：**仅后端**；目标：**`naiba/` 包 + 领域分层 + 单向依赖 + `server.py` 门面**；前置约定：**阶段 0 顺带修复既有缺陷与死代码、补测试护栏**。
>
> 本方案基于 5 份只读深读报告（server 上帝模块 / 模型·视觉·搜索层 / Skill·MCP 层 / 任务·Job·计划层 / 存储·工具·前端），所有行号均为 2026-09 提交 `e8bb87b` 下实测行号。

---

## 0. 背景与目标

### 0.1 现状

- 后端 20 个 Python 文件平铺根目录，约 2.4 万行；前端 `public/app.js` 单文件 7855 行（**本轮不动**）。
- `server.py`（5575 行）同时承担：HTTP 传输层（约 1000–1200 行）、`NaibaChatApp` 组装根、`ConfigStore` 配置 CRUD（约 1120 行）、大量与 HTTP 无关的纯函数工具。
- 各 runtime 文件"名义上已拆分"，但通过 **9 处函数级延迟 `from server import ...`** 反向借用纯函数，构成逻辑环；`APP` 全局被引用 194 处，使模块间实际咬合。
- `tests/` 仅 2 个有效测试文件（`test_updater.py`、`test_workspace_binding.py`），**无任何 server.py 路由测试**；`__pycache__` 中残留 12 个已无源码的历史测试 pyc（test_regressions / test_runs / test_plan6 / test_permission_modes / test_comfyui_tools / test_capability_runtime / test_model_profiles / test_diagnostics / test_harness_primitives / test_plans / test_plan4 / test_build36），说明历史覆盖曾更广。

### 0.2 目标

1. 后端逻辑迁入 `naiba/` 包，按领域分层，**依赖方向单向（DAG）**：
   - 低层禁止 import 高层；运行时**永不 import server 包**；跨层共享一律走注入（构造参数 / 回调 / 窄 Protocol）。
2. `server.py` 退化为**门面 shim**（re-export + `main()` 委托），保证 `launcher.py`、`tests/test_workspace_binding.py`、PyInstaller spec（入口 `launcher.py`）与既有调用点**零改动**。
3. 对外 HTTP API 路径、事件流协议**版式不动**，只挪代码归属；前端不需要任何配合。
4. 按阶段推进：每阶段独立提交、独立验证、可回滚；阶段 0 修复缺陷 + 清死代码 + 补护栏。

### 0.3 不变量（任何阶段都不得破坏）

- 端点路径与 HTTP 语义不变；事件 `type` 与负载字段不变；SSE/NDJSON 流式协议不变。
- `run_events` 表 PK(run_id, sequence) 与 sequence 分配语义不变。
- Run/Job 取消竞态防线不变：`_run_chat` 取消双检（L844/L850/L1158/L1226-1229）、`_persist_aborted_message` 幂等检查（L1531-1537）、3 秒强制取消看门狗（L1437-1468）。
- 工具确认协议 `NEED_CONFIRM:<id>:<reason>:<args>` 与权限模式（confirm/auto/full/deny）行为不变。
- Skill 注入机制不变：冻结集按字节稳定渲染进 system 尾部（保 DeepSeek 前缀缓存）；/ref 引用以用户消息追加且仅首次；>60000 字符只发 `skill_warning` 事件不截断。
- DeepSeek `reasoning_content` 透传、多模态图片路由、缓存命中率优化逻辑不变。

### 1.3 跨模块隐性契约（阶段 4 类型化对象）

1. **`run_context` 字典**（16 键）：`run_id / job_id / conversation_id / owner_session_id / parent_job_id / depth / allowed_tools / skill_policy / job_registry / executor / cancel_event / vision_budget / interaction_mode / routing_message / pull_interjections / mark_interjections_consumed`；跨 async_tasks / plan_runtime / subagent / tool_registry / skill_runtime / vision_runtime 6 方，无类型定义。
2. **事件 type**（约 25 种）：`delta / reasoning_start / reasoning_delta / reasoning_end / status / skills / tool_start / tool_confirm / tool_result / tool_error / vision_* / debug_cache / error / …`；前端 `handleChatEvent`（app.js L5666-5997）与 async_tasks 负载逐字对齐。
3. **消息 metadata 键**：`attachments / reasoning / tool_runs / trace / usage / files / plan_id / plan_step / plan_step_title / aborted / partial / error`；写入方 async_tasks（L1202-1224 / L1544-1556 / L1644-1656），重放方 `build_model_history`（server L2570-2636）。
4. **storage 表契约**：`background_tasks` 同时承载 run 与 job 两类行（`parent_job_id / owner_session_id / progress / current_step / attempt / checkpoint / result` 为迁移列）；`run_events` PK(run_id, sequence)，`append_run_event` 用 MAX+1 分配，读取默认封顶 500 需分页；`plans.steps` 为 JSON 数组（id/title/detail/status/summary）；`cleaned_jobs` 用于区分"已清理"与"从未存在"。
5. **tools 三层**：内置工具（tool_registry **声明** 39 个 + 系统处理器注册表）→ 实际执行器 `ToolExecutor` **在 skill_runtime L382-1103** → MCP（`mcp__<server>__<tool>` 动态注册，仅重开会话进入可用集）。

### 1.4 阶段 0 处理的缺陷与死代码（全部已核实）

**缺陷**
- D1：`_cache_debug_enabled` 两处复制且 ImportError 兜底相反：model_runtime.py:26 → `False`（默认关），skill_runtime.py:36 → `True`（默认开）。修正方向：合并为 `naiba/core/diagnostics.py`，语义统一为 `CACHE_DEBUG_ON 或 NAIBA_DEBUG_CACHE=1`，兜底 **False**（与 server 实际默认一致），并修 server.py:2493 注释"默认开启"→"默认关闭"。
- D2：server.py L3049-3092 的 provider 能力推断族（`_infer_supports_images` 等）在 ConfigStore 之外且 `_infer_supports_images` 函数级延迟 import vision_runtime（L3059）——归类到 config 层时一并迁移。

**死代码（删除，若测试依赖则先 grep 确认）**
- vision_runtime.py:949 死导入 2 个符号；
- mcp_runtime.py：`MCPCallError`（从未 raise/catch）、`MCPRegistry.acquire/release`（全项目无调用方）、`on_event` 回调参数与 `_emit` 事件管道（从未接线，server 只接 on_tools_discovered/on_tools_deregistered）；
- skill_runtime.py：`ToolExecutor.mcp_setup` 死参数、`mcp_registered_note`（无调用方）、`_trim_content_to_token_budget` / `_trim_message_content`（无调用方）、`@staticmethod` 重复（L1986-1987）、`finally: pass`（L1283-1284）、`render_skill_block` 永不返回 None 的死分支（L1921-1922）；
- server→mcp_runtime 私有访问（server L3602-3608 读 `mcp._lock/connections/env`）→ 改为 MCPRegistry 公开方法（如 `connection_env(server_id)`），`Registry` 内直调 `connection._emit`（L423/L472）保留内部使用。

## 2. 目标架构（naiba/ 包）

### 2.1 分层与依赖红线


## 4. 兼容策略与风险

### 4.1 server.py 门面 shim 写法（评审关注点）

```python
# server.py（最终形态）
from naiba.core.history import build_model_history, encode_image_for_model  # 等全部旧符号
from naiba.core.choices import _detect_choice_groups, _detect_choices
from naiba.core.attachments import extract_attachments, _image_intent
from naiba.core.file_changes import file_changes_from_runs
from naiba.core.diagnostics import _cache_debug_enabled, CACHE_DEBUG_ON
from naiba.storage.media import (_process_uploaded_image, _thumb_webp_path,
                                 _uploads_total_bytes, _clean_uploads_cache, ...)
from naiba.config import ConfigStore, default_config, built_in_agents, ...
from naiba.app import NaibaChatApp, APP_TYPE  # APP 类型注解由 http.py 改为类属性持有

def main():  # 保持签名与行为（实例锁/写状态文件/托盘参数等）
    from naiba.app import main_entry
    main_entry()
```

- 维护显式 `__all__`（含私有符号），`from server import *` 语义稳定；
- `APP` 全局在 shim 中保留为 `NaibaChatApp` 类型注解（供 tests 兼容），实际对象由 `naiba.app` 持有并在 `RequestHandler` 构造时注入；
- PyInstaller spec：入口仍为 `launcher.py`，pathex 含根目录，`naiba/` 为普通包自动收集；无需改 spec（验证项）。

### 4.2 风险清单与预案

| 风险 | 影响 | 预案 |
|---|---|---|
| DATA_DIR 二次重绑定（App.__init__ 3095-3124，17 处引用） | 拆包后 import 顺序变化可能取到旧值 | 阶段 3 **第一步**做 PathContext 注入化，任何模块不得再读模块级 DATA_DIR |
| STATIC_ASSET_VERSION import 时磁盘 I/O | 拆包/冻结版路径敏感 | 延后到首次请求，或随 PathContext 注入 |
| 取消竞态（双检/看门狗/幂等重建） | 拆 chat.py 时顺序改动即回归 | 阶段 0 先补 test_run_events 取消用例 + 3 秒看门狗用例；拆时保持 4 条收尾路径原序 |
| run_context/事件两套隐性契约 | 拆 run/ 模块时按字典键耦合 | 拆前先做 §4 的契约清单核对；阶段 4 类型化 |
| 重试矩阵（stream_options/tools/reasoning 三级回退 + 429/502/503/504 退避） | llm/ 拆分最易回归 | test 补"按 HTTP 码行为对照"用例（阶段 0 先补最小集） |
| Sketch 安装逻辑跨层调用（server→skills/install + capability_runtime） | 阶段 3 下沉期间双份逻辑 | 一次迁完并删除旧副本，禁止"复制后慢慢迁移" |
| 外部依赖（mcp SDK 懒加载、pywebview/pystray） | 包化后 hiddenimports | spec 不变即可，若 PyInstaller 报缺再补 hiddenimports（验证项） |
| 测试断裂（tests 顶层 `from server import`） | 只有 2 个测试文件引用 | shim re-export 保证不断 |

### 4.3 回滚策略

- 每阶段一组独立 commit，`git revert <阶段commit>` 即回滚该阶段；
- 阶段间不依赖未提交状态；阶段 1 的 re-export 使阶段 2/3 可随时暂停在"行为等价"状态。
