# Naiba Chat 模块化重构设计方案

> v0.1 草案（待评审）。范围：**仅后端**；目标：**`naiba/` 包 + 领域分层 + 单向依赖 + `server.py` 门面**；前置约定：**阶段 0 顺带修复既有缺陷与死代码、补测试护栏**。
>
> 本方案基于 5 份只读深读报告（server 上帝模块 / 模型·视觉·搜索层 / Skill·MCP 层 / 任务·Job·计划层 / 存储·工具·前端），所有行号均为 2026-09 提交 `e8bb87b` 下实测行号。

## 0. 背景与目标

### 0.1 现状

- 后端 20 个 Python 文件平铺根目录，约 2.4 万行；前端 `public/app.js` 单文件 7855 行（**本轮不动**）。
- `server.py`（5575 行）同时承担：HTTP 传输层（约 1000–1200 行）、`NaibaChatApp` 组装根、`ConfigStore` 配置 CRUD（约 1120 行）、大量与 HTTP 无关的纯函数工具。
- 各 runtime 文件"名义上已拆分"，但通过 **9 处函数级延迟 `from server import ...`** 反向借用纯函数，构成逻辑环；`APP` 全局被引用约 197 处（统计口径 ±3），使模块间实际咬合。
- `tests/` 仅 2 个有效测试文件（`test_updater.py`、`test_workspace_binding.py`），**无任何 server.py 路由测试**；`tests/__pycache__` 磁盘上残留 **15 个 pyc**（12 个不同测试模块名：test_regressions / test_runs / test_plan6 / test_plans / test_plan4 / test_permission_modes / test_comfyui_tools / test_capability_runtime / test_model_profiles / test_diagnostics / test_harness_primitives / test_build36，其中 plan4 / plan6 / regressions / runs 存在 3.12 与 3.14 双版本），说明这些测试曾在本机跑过；但 `git ls-tree 30e860e~1:tests` 只有现役 2 个文件、git 历史中亦无删除记录（唯一相关删除是 1.4.2 的旧测试）——**源码从未入库，无法从 git 恢复**，只能按行为规格重建（§5.2）。

### 0.2 目标

1. 后端逻辑迁入 `naiba/` 包，按领域分层，**依赖方向单向（DAG）**：
   - 低层禁止 import 高层；运行时**永不 import server 包**；跨层共享一律走注入（构造参数 / 回调 / 窄 Protocol）。
2. `server.py` 退化为**门面 shim**（re-export + `main()` 委托），保证 `launcher.py`、`tests/test_workspace_binding.py`、PyInstaller spec（入口 `launcher.py`）与既有调用点**零改动**。
3. 对外 HTTP API 路径、事件流协议**版式不动**，只挪代码归属；前端不需要任何配合。
4. 按阶段推进：每阶段独立提交、独立验证、可回滚；阶段 0 修复缺陷 + 清死代码 + 补护栏。

### 0.3 不变量（任何阶段都不得破坏）

- 端点路径与 HTTP 语义不变；事件 `type` 与负载字段不变；SSE/NDJSON 流式协议不变。
- `run_events` 表 PK(run_id, sequence) 与 sequence 分配语义不变。
- Run/Job 取消竞态防线不变：`_run_chat` 取消双检（L844/L850/L1158/L1226-1229）、`_persist_aborted_message` 幂等检查（L1531-1537）、3 秒强制取消看门狗（L1437-1468）。
- 工具确认协议 `NEED_CONFIRM:<id>:<reason>:<args>` 与权限模式（confirm/auto/full/deny）行为不变。
- Skill 注入机制不变：冻结集按字节稳定渲染进 system 尾部（保 DeepSeek 前缀缓存）；/ref 引用以用户消息追加且仅首次；>60000 字符只发 `skill_warning` 事件不截断。
- DeepSeek `reasoning_content` 透传、多模态图片路由、缓存命中率优化逻辑不变。

### 0.6 重构哲学指引（2026-09-06 对齐，全阶段共同基线）

**① 目标形态 = 分层单向 DAG（依赖图，而非目录图）**

- 图的三类边：`import` 边、运行期调用边（如 async_tasks → app.plans.run_execution）、契约边（run_context 键 / 事件 type / metadata 键 / storage 表结构约定）；**目录层级只是该图的投影**，把文件挪进文件夹并不自动解耦。
- 方向：低层不得依赖高层（core 不知道 run 的存在）；组装只在组合根 `naiba/app.py` 发生；**DAG 只是必要条件**——"不构成环但跨层倒流"的边同样禁止。

**② 边必须显式化（看不见的边是未来的坑）**

- 禁止以"函数级延迟导入"作为解环手段（旧的 9 处清零后**不许复活**）；解环三手段：**下沉纯函数 / 依赖倒置注入 / 契约类型化**。
- 跨模块共享的一切（状态、回调、协议）必须是构造参数 / 注入 / Protocol；禁止经全局 `APP` 中转，禁止字符串键隐式传递（`run_context` 16 键等一律类型化）。

**③ 图可机械验证（不靠人眼）**

- 每阶段提交后运行**依赖图断言测试** `test_dependency_dag.py`（AST 扫描项目内 import），断言"无环 + 无上箭头"；扫描范围随阶段推进从 `naiba/core/` 扩展至整个 `naiba/` 包。该测试是哲学指引落地为 CI 守则的载体，阶段 1 首次引入。

**④ 结构 ≠ 行为（两条线互相独立）**

- DAG 化只回答"依赖往哪流"，行为等价由护栏测试（阶段 0 已建 41 例）与 golden 基线保障；二者不可互相替代。
- 每个阶段收尾的操作性验收新增：**源码测试通过 + 冻结版编译并经用户实测 exe**（本次阶段 0 收尾即执行，防"源码模式跑通 ≠ 分发形态跑通"）。
- **冒烟必须包含 `/api/bootstrap` + `/api/health`**（2026-09-06 教训：ToolExecutor 归位时误搬 SkillCatalog 辅助函数，bootstrap 500 → 前端误弹「连接电脑服务」登录框；只验 health 漏掉了 Skill 扫描路径）。

**⑤ 搬移守则（2026-09-06 五次事故后固化；后续所有大块搬移强制执行）**

1. **三步验收**：① 导入系统性核对——「完整未定义名扫描」：AST 收集全部 Store 绑定（含 lambda / except-as / 推导式），报告任何 LOAD 无绑定者；剩余候选多为 except-as / 注释误报，需人工核实；② 全量 unittest；③ 冒烟必须 `GET /api/health` + `GET /api/bootstrap` **都 200**（bootstrap 覆盖 Skill 扫描等装配路径——只验 health 会漏掉 NameError 类装配故障）。
2. **顶层定义集 diff**：搬出文件定义集 == 目标文件定义集 ∪ 剩余文件定义集（防误搬/漏搬，如 SkillCatalog / `_frontmatter_value` 被裹挟搬走的教训）。
3. **禁用「凭印象拼导入清单」**：优先原样复制源文件头部导入块；新增依赖由「未定义名扫描」兜底——扫描必须覆盖**混合大小写命名**（`normalize_skill_policy` 这类小写函数名曾被"大写常量扫描"漏掉）。
4. **改写型手术（方法→函数 / 正文变换）风险远高于整体搬移**：能整类搬移就整类搬；必须改写时先做原文本引用 / 行为等价核对。2026-09-06 三次连环事故全部源于"方法→函数"改写（常量误卷 / 装饰器与委托错位 / 漏导入），最终方案是**回退为整类搬移**（`SkillAgent` 全类原样迁入 `naiba/skills/agent.py`，零改写）。
5. 每逻辑单元独立提交；每阶段后 PyInstaller 编译一次并交用户实测；若编译因 naiba-chat 进程占用失败，允许直接 kill naiba-chat 进程。
6. **提交卫生**：显式 `git add <文件>`（勿用 `-A`——`build_info.json` 每次编译滚动、`.tmptest/` 为沙箱本地产物，均勿入提交）；`.tmptest/` 已在 .gitignore。
7. **环境纪律**：PowerShell 内联 `python -c "…"` 会破坏转义字符串（多次假警报的根源）——验证脚本一律写到 `.tmptest/*.py` 再执行，并设 `PYTHONPATH=D:\naiba-chat`。

**⑥ 事故记入（2026-09-06 二）：装饰器-绑定错配是未定义名扫描的盲区**

- **事件**：模型「测试连接」报 `name 'self' is not defined`——`RequestHandler._provider_profile` 被装饰为 `@staticmethod` 但方法体引用 `self.app.config`；该缺陷**潜伏于重构之前**（059341e 即存在），只有「模型编辑页内联测试（无 model_key）」这一旁路路径触发，常规冒烟（health/bootstrap）不覆盖。
- **教训**：**整类搬移 ≠ 行为等价**。AST 未定义名扫描器把 `self`/`cls` 视为隐式绑定名（绑定集合包含方法参数），因此对「装饰器与实例绑定的组合」是**盲区**——搬移只验证了"名字可达"，没有验证"调用形态"。
- **新增守则**：① 每个编译/提交时跑**装饰器-绑定一致性静态检查**（`@staticmethod` 方法体禁引用 `self`/`cls`；`@classmethod` 方法体禁引用 `self`），已固化为 `tests/test_static_decorators.py` 永久守门（哲学③ 机械可验证的又一实例）；② 验收用例需覆盖**旁路 UI 路径**（无 model_key 的供应商内联测试、无默认配置的首次启动等）；③ 修复此类历史缺陷时先 `git show <搬移前 commit>:` 对照，确认"搬移引入"还是"预先存在"，汇报时如实归因。

- **二次事故事件（2026-09-06 三，上传 500）**：`_upload` 迁入 app.py 后残留 `getattr(self.app, "config", None)`——搬移脚本的 `self.app.` 替换**只覆盖带点形式**，`getattr(self.app, …)` 无点形式是同一盲区的第二种形态（装饰器盲区是"调用形态"，此处是"引用词法形态"）。**新增守则**：① 任何 `self.app.`→`self.` 脚本搬移后，必须在目标文件跑**残留引用扫描**（grep `self.app` / 旧命名空间前缀，含 `getattr`/`setattr`/字符串形式），已固化进 `test_app_module_has_no_self_app_refs` 守门测试；② 每轮冒烟除通用端点外，需覆盖**用户已实际报过的接口**（上传播放、模型测试、Skill 安装），此前"验证通过/失败"以**端口真实释放后的新进程**为准——停止命令返回 ≠ 端口已释放，复测前先确认旧进程退出（本次教训：旧进程未死导致两次误判）。

### 1.3 跨模块隐性契约（阶段 4 类型化对象）

1. **`run_context` 字典**（16 键）：`run_id / job_id / conversation_id / owner_session_id / parent_job_id / depth / allowed_tools / skill_policy / job_registry / executor / cancel_event / vision_budget / interaction_mode / routing_message / pull_interjections / mark_interjections_consumed`；跨 async_tasks / plan_runtime / subagent / tool_registry / skill_runtime / vision_runtime 6 方，无类型定义。
2. **事件 type**（约 25 种）：`delta / reasoning_start / reasoning_delta / reasoning_end / status / skills / tool_start / tool_confirm / tool_result / tool_error / vision_* / debug_cache / error / …`；前端 `handleChatEvent`（app.js L5666-5997）与 async_tasks 负载逐字对齐。
3. **消息 metadata 键**：`attachments / reasoning / tool_runs / trace / usage / files / plan_id / plan_step / plan_step_title / aborted / partial / error`；写入方 async_tasks（L1202-1224 / L1544-1556 / L1644-1656），重放方 `build_model_history`（server L2570-2636）。
4. **storage 表契约**：`background_tasks` 同时承载 run 与 job 两类行（`parent_job_id / owner_session_id / progress / current_step / attempt / checkpoint / result` 为迁移列）；`run_events` PK(run_id, sequence)，`append_run_event` 用 MAX+1 分配，读取默认封顶 500 需分页；`plans.steps` 为 JSON 数组（id/title/detail/status/summary）；`cleaned_jobs` 用于区分"已清理"与"从未存在"。
5. **tools 三层**：内置工具（tool_registry **声明** 39 个 + 系统处理器注册表）→ 实际执行器 `ToolExecutor` **在 skill_runtime L382-1103** → MCP（`mcp__<server>__<tool>` 动态注册，仅重开会话进入可用集）。

## 4. 兼容策略与风险

### 4.1 server.py 门面 shim 写法（评审关注点）

```python
# server.py（最终形态）
from naiba.core.history import build_model_history, encode_image_for_model  # 等全部旧符号
from naiba.core.choices import _detect_choice_groups, _detect_choices

from naiba.app import NaibaChatApp, APP_TYPE  # APP 类型注解由 http.py 改为类属性持有

def main():  # 保持签名与行为（实例锁/写状态文件/托盘参数等）
    from naiba.app import main_entry
    main_entry()
```

- 维护显式 `__all__`（含私有符号），`from server import *` 语义稳定；
- `APP` 全局在 shim 中保留为 `NaibaChatApp` 类型注解（供 tests 兼容），实际对象由 `naiba.app` 持有并在 `RequestHandler` 构造时注入；
- **re-export 面收窄（2026-09-05 外审修订）**：shim 只服务两类消费者——① `launcher.py`（`RequestHandler` / `APP` 类型 / `STATUS_PATH` / `RESOURCE_DIR` / `write_status` / `acquire_instance_lock` / `NaibaChatApp` / `main`）；② `tests/test_workspace_binding.py`（`from server import ConfigStore`）。其余符号仅为 server 自身存留代码可达而保留；阶段 3 收口后凡 server 内已无调用点的 re-export 一律移除，**`server` 不再承担任何 runtime 的依赖中转**；
- PyInstaller spec：入口仍为 `launcher.py`，pathex 含根目录，`naiba/` 为普通包自动收集；无需改 spec（冻结版实测项，见 §4.2）。

### 4.2 风险清单与预案

| 风险 | 影响 | 预案 |
|---|---|---|
| DATA_DIR 二次重绑定（App.__init__ 3095-3124，17 处引用） | 拆包后 import 顺序变化可能取到旧值 | 阶段 3 **第一步**做 PathContext 注入化，任何模块不得再读模块级 DATA_DIR |
| STATIC_ASSET_VERSION import 时磁盘 I/O | 拆包/冻结版路径敏感 | 延迟化并明确 **lazy-once 缓存**（首次访问计算并缓存，或随 PathContext 注入时计算），禁止每请求重算磁盘哈希 |

| 取消竞态（双检/看门狗/幂等重建） | 拆 chat.py 时顺序改动即回归 | 阶段 0 先补 test_run_events 取消用例 + 3 秒看门狗用例；拆时保持 4 条收尾路径原序 |
| run_context/事件两套隐性契约 | 拆 run/ 模块时按字典键耦合 | 拆前先做 §4 的契约清单核对；阶段 4 类型化 |
| 重试矩阵（stream_options/tools/reasoning 三级回退 + 429/502/503/504 退避） | llm/ 拆分最易回归 | test 补"按 HTTP 码行为对照"用例（阶段 0 先补最小集） |
| Sketch 安装逻辑跨层调用（server→skills/install + capability_runtime） | 阶段 3 下沉期间双份逻辑 | 一次迁完并删除旧副本，禁止"复制后慢慢迁移" |

| 测试断裂（tests 顶层 `from server import`） | 只有 2 个测试文件引用 | shim re-export 保证不断 |
