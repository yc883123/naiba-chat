## 三、最近三次事故（完整脉络）

### 事故 1：`SKILL_CONTENT_WARN_CHARS` is not defined
- 现象：带 Skill 对话运行时报错（AI 消息"请求失败"）。
- 根因：skills 一批① 的首版切割区间 `[SKILL_POLICY_MODES…DEFAULT_CONTEXT_WINDOW)` 把 `SKILL_PROMPT_HEADER`/`SKILL_CONTENT_WARN_CHARS`（技能注入常量）卷进 policy.py；SkillAgent 运行期引用 → NameError。
- 修复：`4381b6f` 常量归位 skill_runtime；policy.py 只留策略常量。
- 教训：单测/bootstrap 不覆盖的**运行时路径**（Skill 注入/体量告警）需要升级守则。

### 事故 2：`SkillAgent._estimate_content_tokens() takes 1 positional argument but 2 were given`
- 现象：同场景继续报参数个数错误。
- 根因：首版"方法→函数改写"手术（正文替换/装饰器处理/去 cls）多处错位：部分方法保留原体但丢装饰器、部分变薄委托，接口错乱。
- 处置：**整体回退改写方案**，改为"整类搬移"（`3f656f8`）——SkillAgent 全类+内部辅助+专属常量**原样**搬入 `naiba/skills/agent.py`，零改写、零语义风险；skill_runtime 收为兼容导入。policy/context 仅搬模块级。
- 附带修复：搬运区间误删 `_frontmatter_value`/`_skill_display_name`（SkilCatalog 需要）→ 从 git 盘点区间后精确恢复，`test_skill_catalog` 护栏恢复通过。

### 事故 3：`normalize_skill_policy` is not defined
- 现象：整类搬移后同场景继续报错（类方法在 agent.py 命名空间找不到该函数）。
- 根因：agent.py 忘记导入 `normalize_skill_policy`（小写函数名，旧"大写常量扫描"覆盖不到）。
- 修复（`7ec5fa5`）：agent.py 补导入 + 定义 `EventCallback` 别名；policy.py 清除与 skill_runtime 重复的 `_frontmatter_value`/`_skill_display_name`；**顺手排雷**——`ActiveRunError` 下沉 `naiba/core/exceptions.py`（chat.py mixin 直接 raise 它却未持有定义，chat→manager 导入会成环；此雷只在"回复中再发第二条消息"时触发），manager/chat 改为共同引用叶子层异常。
- 当前状态：**待用户复测确认**（复测重点：带 Skill 消息、并发第二条消息）。

## 四、固化守则（新对话所有大块搬移强制执行）

1. **三步验收**：①导入系统性核对（"完整未定义名扫描"：AST 收集全部 Store 绑定含 lambda/except-as/推导式，报任何 LOAD 无绑定者；本项目剩余候选均为 except-as/注释误报，需人工核实）；②全量 unittest；③冒烟必须 `GET /api/health` + `GET /api/bootstrap` 都 200（bootstrap 覆盖 Skill 扫描等装配路径）。
2. **顶层定义集 diff**：搬出文件定义集 == 目标文件定义集 ∪ 剩余文件定义集。
3. **禁用"凭印象拼导入清单"**：优先原样复制源文件头部导入块；新增依赖由"未定义名扫描"兜底。
4. **改写型手术（方法→函数/正文变换）风险远高于整体搬移**：能整类搬移就整类搬；必须改写时先做原文本引用/行为等价。
5. 每逻辑单元独立提交；每阶段后 PyInstaller 编译一次并交用户实测；若编译因 naiba-chat 进程占用失败，允许直接 kill naiba-chat 进程。
6. 提交卫生：**显式 `git add <文件>`**（勿 `-A`——`build_info.json` 每次编译滚动、`.tmptest/` 为沙箱本地产物，均勿入提交）；`.tmptest/` 已在 .gitignore。
