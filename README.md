# Naiba Chat 2.0.0 Beta

Naiba Chat 是运行在 Windows 本机的通用 AI 自动化工作台。它把在线或本地模型、内置工具、后台任务、Skill、MCP、视觉工具和文件产物统一到一个对话界面中。

2.0.0 Beta（重构版）在 1.7.9 的基础上完成后端全面模块化重构：核心代码迁入 `naiba/` 包、依赖图单向无环、`server.py` 收口为门面、契约（RunContext/EventType/MetadataKeys）显式化；HTTP API 与事件协议版式不变，前端零配合。详见下方「2.0.0 Beta 主要能力」。

## 2.0.0 Beta 主要能力

- **后端全面模块化重构（阶段 0–4）**：原先约 2.4 万行堆叠在根目录的后端代码迁入 `naiba/` 包（组装根/传输层/配置/存储/运行/工具/技能/模型/视觉/网络等领域分层），依赖图单向无环、机械可验证（DAG 守门测试）；`server.py` 收口为 136 行门面，HTTP 层仅剩薄包装与传输职责，业务逻辑全部下沉至 `NaibaChatApp` 与领域模块。
- **路径与配置**：`PathContext` 统一管理源码/冻结双模式目录（冻结版固定 `%LOCALAPPDATA%\NaibaChat`，旧数据迁移与自定义数据目录切换语义保留）；`ConfigStore` 迁入 `naiba/config.py`；静态资源版本哈希改为 lazy-once。
- **契约化**：`RunContext`（18 键 + 校验工厂）/`EventType`（44 种，与前端反查对齐）/`MetadataKeys` 显式化；`AppContext`/`ConfigView` Protocol 注入收窄（14 处 `app: Any` → `AppContext`）。
- **修复与清理**：模型测试连接 `NameError`（`@staticmethod`+`self` 错配）与上传 500（`self.app` 残留引用）等搬移期缺陷；诊断开关兜底统一；死代码清理（MCP 诊断管道、废弃插话等）。
- **守门测试**：新增权限矩阵（full/confirm/auto/deny 全模式）、装饰器-绑定一致性、`self.app` 残留引用扫描等网格化守门，共 83 个单测；全量功能回归（11 域 48 项）通过。
- **工具系统增强**：视觉类工具单入口（vision_analyze 按会话模型能力自动分流 + vision_image_ops 本地图像计算）；移除 call_mcp 网关；多模态/文本模型同一工具集，退役工具自动迁移/提示；DeepSeek 思考模式工具轮兼容修复（reasoning item 按官方 Schema 回传：`reasoning_text` 内容块列表 + 服务端唯一 id，旧历史无 id 自动合成兜底）；Harness 兼容别名（read/write/edit/grep）从模型可见工具清单隐藏（执行兼容保留）；工具返回对模型可见性统一（机器字段剥离、截断带标记、前端展示与模型上下文同源；vision_image_ops 产物路径对模型保留，供其引用裁剪/热力图产物）；glob_files 并入 list_directory（单入口枚举）。
- **行为兼容**：对外 HTTP API 路径、事件流协议与前端完全不改；13 个根模块保留兼容 shim（`from naiba.X import *`）；`launcher.py`/PyInstaller spec 零改动。
- **历史数据管理**：推理流保持逐词实时显示、回复完成后自动整理为整段思考（事件流不再逐 token 累积）；终态任务快照自动收缩；升级时自动压缩存量历史数据（迁移前先整库备份到 `data/backups`）；设置页「历史数据管理」可查看数据库占用并一键压缩回收空间；实测 400MB 存量库压缩至 ~90MB，继续会话发送给模型的历史消息逐字节不变（前缀缓存命中不受影响）。
- **时间线与用量可观测**：活动时间线规则定稿（思考块一律折叠、思考/工具严格物理序、最终答复固定时间线末尾、每次模型请求开始处以横线分割，与用量明细的请求序号对应）；流式期间消息尾端常驻用量框，每完成一次模型请求即刷新缓存命中率/tokens（最后一次请求口径）与**生成速率**（输出 tokens ÷ 该次请求耗时），完成后显示本轮总耗时、**平均速率**与完成日期，「请求明细」展开逐次请求的 token/命中率/速率/耗时；会话顶部新增「首次请求上下文」折叠卡，可查看第一轮发送给模型的内容（完整系统提示词原文、工具 JSON 定义、生成参数），第一轮完成后即时显示（终态事件后立即拉取，切换会话时同样刷新）。
- **文件上传流式化**：上传改为 multipart 流式直传（内存更省、真实传输进度、单文件可取消、多文件并行上限 3、80MB 前端前置校验）；上传内容自动去重（重复文件复用既有缓存）、按日分目录存储、移除待发送附件时自动清理未引用文件；上传前/上传中的图片缩略图不再请求空路径。
- **缓存管理**：图片/PDF/视频/音频等统一「缓存文件」统计（设置页打开即刷新实时值）；超限自动清理（阈值默认 256MB、设置页可调/填 0 关闭）**只删未被消息引用的最旧文件**——历史消息引用的附件永不自动删除；手动清理与自动清理共用同一阈值口径，界面明确提示「按时间从旧到新、不区分是否被引用」。
- **PDF 解析与识别**：内置 PDF 工具三件套——`read_pdf`（文本层提取：页标记、单次 30000 字符/50 页、截断续读提示、扫描版自动引导转页图）、`pdf_render_pages`（页面渲染为 PNG 页图，可复核的 AI 看图素材）、`pdf_zoom_region`（局部高清放大：小字/表格/图表看不清时矢量源重渲精读）；上传或提及 PDF 后模型按需提取文本/渲染页图并用 `vision_analyze` 识图；页图缓存在受管数据目录（自动清理覆盖），不污染工作区；`read_file` 对 PDF/图片/二进制文件不再输出乱码，改为明确提示并引导对应工具。
- **多图分批读取**：`vision_analyze` 单批默认 4 张（装载/分析两路径统一），超出自动分批注入并带批次标注（共 N 张/已展示前 M 张）——多页 PDF、多图分析时模型清晰知道"还有剩余",不再因静默截断而误解；用户上传附件与宿主托管产物（uploads/generated）在读取策略中视为可信根，免越界确认（真正的工作区外路径仍确认）。
- **纯附件发送**：输入框不写文字也能直接发送文件/图片（拖入、粘贴、附件按钮均可）；发送按钮按可用性变化——无可发送内容时灰暗禁用，可发送时恢复实心主色，上传未完成或上下文已满时禁用并给出原因提示；仅发附件时模型侧会明确收到「用户未输入文字，只发送了以下附件」+ 附件路径，不会凭空脑补用户诉求；纯附件首轮会话标题自动取首个附件名；发送按钮状态同样跟随程序化填字刷新（快捷消息插入、技能与 `@` 引用回填、选择按钮写入后即时更新）。
- **@ 引用工作区文件/目录**：输入空格 + `@` 弹出工作区目录列表（懒加载，只列当前目录，隐藏 `.` 开头的条目），方向键选择、Tab 进入子目录 / Shift+Tab 返回上级、Enter 或点击即引用；目录条目右侧另有箭头按钮可直接进入（手机端无 Tab 键的替代入口），列表首项为「返回上一级」；选中目录时名称左侧显示 Tab 键提示。引用后输入框与消息气泡保留 `@相对路径` 高亮，发送给模型时自动替换为该文件的绝对路径（目录保留尾部分隔符，便于模型处理整目录）；只有工作区内真实存在的路径才会被替换，邮箱等普通 `@` 文本不受影响。
- **快捷消息面板**：输入区底部新增「快捷消息」按钮，点击展开常用提示词列表（**独立列表**，与「开始新对话」页的自定义指令互不影响，各自增删改）；**每条只有正文、不用起标题**（列表以正文首行作标题、其余行折叠预览，新增/编辑弹窗只填正文）；列表默认按「使用次数 × 2 + 新鲜度加分」排序——常用条目稳定靠前，新添加的条目在 7/30/90 天内有曝光窗口不会永远沉底，并列时新增的在前；点击条目把正文插入输入框（可继续编辑再发送）并累计使用次数，行内 `✎` 编辑、`✕` 删除；面板在窄屏上自动贴边对齐，触屏下操作按钮常显。
- **图片查看**：点击会话里的图片打开大图，灯箱内可用左右按钮、`←`/`→` 键或**点击屏幕左右半屏**连续浏览当前会话的全部图片（按在对话中出现的顺序，首尾循环），底部显示 `当前 / 总数`；**滚轮缩放、缩放后拖动平移、双击复位**（触屏支持单指拖动、双指捏合、双击切换），`Esc` 或点击空白处关闭。输入区待发送的附件与右侧文件面板里的图片仍按单张查看。
- **工具产物就地显示（多媒体内嵌）**：工具产出的图片/视频/音频不再等整轮结束才集中堆到消息末尾，而是**紧跟产生它的那次工具调用就地显示**——流式期间工具一返回就出现，工具块保持折叠、媒体始终可见，同一张图不会重复显示（消息末尾网格自动跳过已就地渲染的附件）；提取策略由工具在注册表显式声明（`metadata["media"]`：`inline`/`intent_gated`/`never` × `none`/`scan`/`structured`），不再按工具名枚举猜测，且只对成功的工具结果提取（失败信息里的路径不会变成破图）；单次调用按类型分桶上限（图 20 / 视频 8 / 音频 8）**先截断再入缓存**（列一次目录不会把几百张图拷进缓存卡住），超出时明确提示「共 N 个媒体，仅显示前 M 个」；`/api/file` 支持 Range 请求（视频/音频进度条可拖动、大文件不整包进内存），用户上传与工具产出的视频/音频都能在气泡里直接播放；GIF 保留动画并生成首帧缩略图（此前缩略图必然 404 破图）；后台任务（ComfyUI 等）产物在任务完成后**自动挂回发起它的那条消息**、挂到对应工具调用下方，无需再追问模型；缓存改为按内容哈希（修复 ComfyUI 同名覆盖时命中旧图）并修复带查询串的图片 URL 被截断（表现为「任务完成却看不到图」）。
- **开始页预设可编辑**：开始页内置预设（通过 MCP/HTTP 调用 ComfyUI、设置本地 Comfy MCP、列出可用工具/所有文件、等待用户指令）与自建指令同权——悬停即可编辑与删除；删除后底部出现「恢复默认预设」一键找回；升级后新增的内置预设自动出现，已删除的按预设 id 记录、不会复活；编辑内置预设保留其说明与图标。
- **思考强度交互**：思考按钮点击只做一件事——展开/收起强度列表（此前收起时会顺带切档）；列表高亮当前档位，输入框下方与「就绪」同行常显当前强度（`思考 自动/关闭/低/中/高`）。
- **Skill 脚本编码规范**：安装/编辑 Skill 的说明补充脚本规范——脚本统一放 Skill 目录的 `scripts/` 子目录，读写文件显式指定 UTF-8（冻结版默认编码跟随系统 locale，裸 `open()` 写中文会乱码）；同时修复 Skill 脚本输出中文乱码（隐藏入口强制子进程 UTF-8 输出）。
- **输入区精简**：移除「轻量」与「富文本」两个开关——工具与 Skill 的能力范围完全由 Agent 设置（Agent 的工具集 / 技能集）决定，不再有会话级轻量模式；富文本始终开启（安全白名单 HTML 正常渲染）。同时移除会话界面中「本次对话规则：未设置」提示条（会话规则已统一由 Agent 的系统提示词决定）。
- **会话收藏与侧栏交互**：会话条目的齿轮改为**五角星**，点击即收藏/取消收藏（乐观更新，失败回滚）；侧栏最下方新增跨工作区的「已收藏」分组，收藏的会话**同时保留在原工作区**（两处都显示，不会"消失"），且**收藏不会重排工作区内的会话顺序**（收藏只改标记、不推进更新时间，避免收藏项被顶到最前、启动时"最新 5 条"被挤占）；重命名与删除并入条目的「⋯」菜单（fixed 挂到 body 不被侧栏裁剪，Esc 或点击外部关闭），**新建工作区也改为对话框**（选目录 → 填名称，不再依赖内嵌浏览器的原生 prompt）；条目更紧凑（高度 40→34px、标题 13→12.5px、时间 11→10px、行内间距 6→4px）；**滚轮步进按 1.5 倍接管**（≈150px/格，触控板小步进仍走原生），并修掉三处手感问题——虚拟列表的滚动上限此前漏算容器 padding（每次滚动被回写吃掉 16px，"越滚越慢"、底部到不了）、滚动时每帧重写 DOM（改为只在可视行区间变化时重绘，实测 160px 滚动的重绘次数从 20 降到 ≤8）、悬浮分组表头时删除按钮撑高行（改为绝对定位 + visibility，划过不再抖动）。
- **会话级系统提示词退役**：系统提示词**只有一个来源——Agent**（`agent.system_prompt`，为空时回退全局默认）；顶栏「对话设置」按钮、会话条目齿轮入口与整个对话框（含流式输出开关、清空对话）一并移除，`conversations.system_prompt` 作为遗留列保留但**不再注入模型**（历史值仍可在「首轮上下文」卡片里看到当时原文）；角色卡导入与快捷提示词套用统一迁到**设置 → Agent → 编辑**的「系统提示词（预设与规则）」行下方（角色卡为**追加**语义，不覆盖手写内容；超 12000 字符截断并提示），快捷提示词的增删改仍留在「设置 → 快捷提示词」。

### 历史能力（1.7.8 及更早）

- **对话快捷系统提示词**：新增「设置→对话快捷系统提示词」，可新增/编辑/删除/搜索可复用的系统提示词预设；对话设置中可直接选择预设一键填充系统提示词，编辑预设不会改动已保存的对话。
- **角色卡自动收录**：导入 SillyTavern 角色卡 PNG 解析成功后，自动把该角色的人设文本收录为一条快捷系统提示词，无需手动复制。
- **更新检查自动选中新版本**：检查更新完成后自动在下拉框中选中新版本，无需展开下拉框即可看到有更新；手动选择版本后仍按用户选择保留。

### 历史能力（1.7.7 及更早）

- **文件预览隔离**：右侧文件面板的 Markdown 预览改用独立的 `markdownFilePreview` 渲染入口，固定按纯文本/Markdown 渲染，不受对话渲染开关影响，逻辑更清晰。
- **渲染性能优化**：内容不含任何 HTML 标签的消息在富文本还原阶段直接原样返回，跳过正则解析，降低大段纯文本回复的渲染开销。

### 历史能力（1.7.6 及更早）

- **对话富文本渲染**：AI 回复中的安全白名单 HTML 富文本（`b`/`i`/`u`/`s`/`span` 与 `font color` 彩色文字）渲染为实际效果；渲染前先整体 HTML 转义、仅对白名单标签按安全规则还原，颜色只允许标准颜色名或十六进制色值，注释一律剔除，其余标签保持纯文本显示，杜绝注入。右侧文件面板中的 Markdown 预览固定按纯文本渲染。
- **文件面板可拖宽**：右侧文件面板新增左缘拖拽分隔条，宽度可在 280px 至窗口一半之间自由调整并记忆（重启保留），不再固定；图片预览取消 58vh 高度上限、改为面板内纵向滚动，可完整查看高图。

- **Job 查询与状态提示分级**：跨会话查询 Job 时区分「记录已被清理」与「Job ID 从未存在」；job_status 按状态给出下一步指引（completed 用 job_output 读结果、运行中用 job_wait 等待等）；用户消息含明确 Job ID 时直接验证、不先检索历史。
- **SillyTavern 角色卡解析增强**：parse_sillytavern_card 对 chara 负载先尝试 gzip 解码并兼容 data 字段包裹，支持更多角色卡导出格式。

- **SillyTavern 角色卡导入**：对话设置中新增「导入角色卡 PNG」，由服务端解析 PNG 内嵌的 ccv3/chara 元数据（兼容 gzip 压缩），把姓名、性格、背景/场景、说话示例、开场白、角色说明、后置指令等字段归一化为系统提示词人设文本，一键填入即可扮演该角色；当前 Agent 自带系统提示词时会提示建议切换到提示词留空的 Agent。
- **细节优化**：会话列表的对话设置按钮在未悬停时改为半透明可见，不再完全隐藏，更易发现。

- **工作区名称绑定**：会话所属工作区（分组）与磁盘目录改由服务端统一绑定——指定已注册工作区时目录一律取其注册路径，不再信任客户端随分组提交的目录；分组名不存在会直接拒绝并给出明确提示。
- **切换分组即切换目录**：把会话切换到某个工作区分组时，该会话的磁盘工作区同步指向该分组注册目录；「移至未分组」只改侧栏分类、保留原有目录，不会移动文件。
- **启动自动修复**：启动时检查全部会话，凡分组指向已注册工作区但目录与注册值不一致的自动改回注册目录；未分组或指向已删除分组的会话保持原样，避免误搬文件。
- **状态同步**：切换工作区后前端立即以服务端返回的目录刷新界面，侧栏分组、底部提示与磁盘目录保持一致。

- **手机端渲染优化**：修复移动端横向滚动条问题（视口宽度改用 100% 并隐藏横向溢出）；顶部模型/Agent 选择器改为网格布局自动换行，操作按钮在窄屏下换行到第二行，超小屏（≤380px）降级为两列；输入框在窄屏下完整占宽，图标与发送按钮不再被压缩；底部工作区、权限开关等元信息在超小屏改为单列排列。

- **暂停/取消竞态修复**：一次暂停立即中断当前事件流、看门狗与待执行重连，并停止轮询恢复；「正在停止」期间禁止发送和恢复旧 Run，服务端确认终态后才恢复；取消父 Run 会级联取消子 Job 与 follow-up Run；完成/暂停并发窗口加锁，取消后不再创建自动 follow-up。
- **断线重连稳定**：重连复用同一回答气泡并从最后事件序号继续，不再重复回放；`/api/chat/cancel` 支持通过 `conversation_id` 定位尚未返回 `run_id` 的 Run；未处理插话保留在记录中并标记为停止，不会自动发送；Job 即使在轮询返回的竞态中完成，也会服从已有取消标记。
- **RunningHub 多媒体生成**：内置 runninghub 技能，覆盖文生图、图生视频、文生视频、TTS、音乐、3D 建模、图片放大、AI 应用（webappId）等 420+ 端点；支持 AI 站（runninghub.ai）与 CN 站（runninghub.cn）双站点，技能随 EXE 打包，升级后启动时自动同步到本地数据目录。

- **失败内容保留**：在线请求异常（如 HTTP 500）时已输出的思考/部分回复/工具活动不会被错误信息覆盖丢失，会重建为「未完成」assistant 消息持久化并保留独立错误提示，刷新/重渲染/后续上下文可见。
- **启动错误清晰**：数据目录/锁文件不可写等权限/环境问题不再误报为「已在运行」，会给出具体目录与原因；启动失败以简洁中文提示退出，不再输出堆栈。

- **左侧边栏改进**：会话列表虚拟化/懒加载、默认折叠、可拖拽调宽，交互更轻量清晰。
- **意图直接触发工具**：工具不再依赖先启动某个 Skill。Skill 只提供领域说明和流程建议，不是能力开关。

- **会话工具集固化**：会话可用工具在首条消息时固化（`enabled_tool_ids` / Agent 的 `tool_scope`），之后不可中途更改；工具选择页支持按分类「全选/全不选」，联动工具须同时选中。
- **更少的中断确认**：读取、检查和常规工作区操作可按权限模式自动执行；只有高风险操作、缺少凭据或不可推断的关键选择才需要用户确认。

- **可校验更新**：更新检查基于 GitHub Releases 版本列表，支持在设置中选择版本安装与回退；每个候选版本都会校验 manifest（仓库、commit、文件名、SHA-256）与可执行文件有效性，任何一项不一致都会拒绝安装并给出明确原因。

## 开始使用

### 使用 Windows 版本

1. 下载 `naiba-chat-2.0.0-beta-windows-x64.zip`。
2. 解压到一个可写目录。
3. 运行 `naiba-chat.exe`。
4. 在设置中添加在线 API 或本地模型服务。

首次运行会创建本地数据目录。升级时请直接替换程序文件，不要删除原有 `data` 目录和配置文件。

### 从源码运行

需要 Windows、Python 3.11 或更高版本。

```powershell
git clone https://github.com/yc883123/naiba-chat.git
Set-Location naiba-chat
python -m pip install pywebview pystray pillow "mcp==2.1.1"
python server.py
```

服务默认地址为 `http://127.0.0.1:8765`。

## 模型配置

在“设置 → 模型”中添加供应商，填写：

- API 地址
- API Key（本地服务通常可以留空）
- 模型名称
- 请求格式
- 是否支持图片输入
- 上下文长度和生成参数

本地模型建议先使用界面中的连接测试确认模型目录、文本推理和图片能力。模型是否能稳定执行工具，仍取决于模型自身的工具调用能力和上下文能力。

## ComfyUI 与 MCP

Naiba Chat 默认连接：

```text
ComfyUI HTTP API:  http://127.0.0.1:8188
```

使用前请确保 ComfyUI 已启动，并且目标节点、模型和素材在 ComfyUI 中可用。

当前内置流程接收 ComfyUI **API 工作流**。前端保存的 UI JSON（通常包含 `nodes` 和 `links`）不能直接提交，需要先在 ComfyUI 中导出 API 格式。

任务提交后由宿主完成以下工作：

1. 校验并规范化工作流参数。
2. 向 `/prompt` 提交任务。
3. 轮询任务历史和执行状态。
4. 自动收集图片、视频或音频产物，缓存到受管理数据目录并生成缩略图。
5. 附加到最终消息（中止/取消的轮次也会展示已生成的产物）。
6. 在聊天界面提供预览或下载。

推荐的工作流修改方式：对已有工作流文件，用 `read_file`/`comfyui_prepare_workflow` 读取结构，用 `edit_file` 做局部精确替换（改提示词/seed/尺寸等），再用 `comfyui_batch` 的 `workflow_paths` 提交文件路径；不要整段内联大工作流 JSON。

这条链路不要求模型读取产物本身。需要评价画面、OCR、定位对象或比较图片时，用户应明确提出分析要求；用户明确要求「保存/复制到指定目录」时模型会实际执行。

### MCP 说明

- 应用启动时自动连接所有已启用的 MCP 服务，并对启动时未连上的服务做周期重试。
- MCP 工具以 `mcp__<server>__<tool>` 形式注册进当前会话的可用工具集；会话工具集在首条消息时固化。
- `call_mcp(server, tool, arguments)` 只能调用**当前会话可用集内**的 MCP 工具；若目标工具不在可用集内，会提示用户重开会话、在 Agent 工具勾选里加上该 MCP 服务后再用。
- `register_mcp` 只是把服务登记进配置，其工具会在**重开会话后**进入新会话的可用集，本会话内不会因注册而新增可用工具。

## 工具、Skill 与 MCP 的关系

- **内置工具**：由当前任务意图直接触发，例如文件操作、命令执行、后台任务、ComfyUI 和视觉处理。
- **Skill**：提供特定领域的说明、模板、脚本和检查清单，不决定工具是否可用。
- **MCP**：接入外部工具服务；只有任务明确需要对应 MCP 服务时才会连接或调用。

因此，生成图片不需要先启动短剧 Skill，普通编程、资料整理、自动化处理和媒体任务也使用同一套运行机制。

## 数据与安全

- 对话、设置、附件和任务状态保存在本地数据目录。
- 缓存文件（用户上传与宿主产物的图片/PDF/视频/音频等）统一存于受管数据目录（用户上传 `data/uploads`、生成产物 `data/generated`），设置页可查看合计大小、按时间清理旧缓存（清理为手动操作，会按时间从旧到新删除最旧文件、不区分是否被引用）并配置自动清理阈值（默认 256MB，自动清理只删未被消息引用的最旧文件）。
- API Key 不应提交到 Git；示例配置不包含真实凭据。
- 局域网访问需要访问口令，默认仅本机访问时不要求口令。
- 文件预览只允许应用工作区和受管理数据目录（`data/uploads`、`data/generated`）中的文件。
- 高风险写入、删除、外部发布和凭据操作仍受权限策略保护。

## 自动更新校验

发布资产包含：

- `naiba-chat.exe`
- `naiba-chat-update.json`
- `naiba-chat-2.0.0-beta-windows-x64.zip`

更新器会验证清单中的仓库、提交、文件名和 SHA-256。下载文件还必须是有效的 Windows 可执行文件；任何一项不一致都会终止安装。

## Beta 说明

这是 2.0.0 Beta，适合实际使用和反馈，但仍有以下边界：

- 不内置 ComfyUI、模型权重或第三方生成服务，需用户自行安装和配置。
- 不同模型的工具调用质量差异较大，小型模型可能无法稳定完成长链任务。
- ComfyUI 自定义节点和工作流输入差异很大，复杂模板仍可能需要一次参数适配。
- 自动化任务应在交付前检查最终文件；涉及发布、删除或覆盖的重要操作应保留备份。
- MCP 工具仅在重开会话后才会进入会话可用集；若模型发现 MCP 服务存在但其工具不在当前会话可用范围，会提示用户重开会话。
